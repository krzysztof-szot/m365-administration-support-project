# Evidence handling

No implementation evidence has been collected.

After each exercise, use a stage-specific folder such as `stage-04/` with numbered captures and a short index. Record the tested identity/role, client, action, expected behavior, actual result and material propagation delay.

Configuration screenshots and functional results are different evidence. A saved permission setting alone does not establish allowed or denied access. Recovery claims must match actual restored content or behavior.

Publish only reviewed synthetic or redacted captures. Keep tenant-specific configuration, billing records, credentials, tokens, recovery codes, real correspondence and raw reports outside the repository. Ignored directories include `local-output/`, `local-config/` and `raw-evidence/`.

Do not fabricate logs, NDR codes or passing checks. If a service is healthy, record that observation rather than claiming a Microsoft outage was resolved.
